# 长任务规范：让长等待活过会话重启

> 适用范围：本机 DSH（DeepSeek Harness）里由 claude-driver / dsh-claude-code
> 驱动的会话。规则同时落在三处，保持同步：
> 1. `~/.dsh/.agent-presets/<preset>/agent.cordis.yml` 的 persona（管住 DSH 主模型/子代理）
> 2. `~/.claude/CLAUDE.md`（管住被委派的 Claude Code）
> 3. 本文件（仓库内的移植文档，新机器照此部署）

## 问题：为什么会话里的 Monitor / 后台 shell 会消失

claude-driver 的机制是**每轮对话 = 一个新拉起的 Claude Code CLI 进程**，回合结束进程
退出；下一轮用 resume 续接同一会话。因此：

- 寄生在 CLI 进程里的东西（后台 shell、监视器、轮询循环）**随进程退出而消失**；
- 进程非正常退出时（abort／硬杀），连"任务完成通知"都一起丢——表现为
  "No completion record was found for this background shell command from the
  previous session ... it may have been running when the previous Claude Code
  process exited"；
- 能活过重启的只有两类：**独立 OS 进程 + 磁盘持久化**的东西。

## 铁律

凡需要跑**超过 1 分钟**的任务，禁止用当前会话的 shell 起后台任务
（会话/宿主进程一重启就丢失，且无完成记录）。必须二选一：

1. **一次性长任务 → `claude_code` 委派**
   - `run_in_background: true`（立刻返回 jobId，不占当前回合）
   - `timeoutMs` 设足（≥ 1 小时），配合 `ENABLE_PROMPT_CACHING_1H=1` 省缓存重写
   - 结果必须写文件落盘，禁止只存在于最终回复里

2. **常驻监视器 → 独立进程 + 日志落盘**（Windows 等效 setsid/nohup）

   ```powershell
   Start-Process powershell -WindowStyle Hidden -ArgumentList '-File <脚本>' `
     -RedirectStandardOutput <日志> -RedirectStandardError <日志>.err
   ```

   进程与父进程脱离；状态通过读日志/状态文件观察，不依赖会话存活。

## 判断标准

任务运行期间，**必须能从磁盘文件或任务登记处读到它的进度**。
如果当前回合/进程死了就什么都查不到 → 这个起法是错的，换上面两种。

## 与驱动内既有保护的关系

| 机制 | 覆盖什么 | 局限 |
|---|---|---|
| `waitForBackgroundTasks` | 正常结束的一轮：持有本步直到后台工作跑完 | abort／硬杀无效 |
| `harvestOrphanedSubagents` | 已经死掉之后：从 transcript 捞回过程产出 | 捞不回从未生成的内容 |
| **本规范** | **从一开始就不把长任务押在当前进程上** | 需要模型遵守（见上方三处落点） |

## 配套：缓存 TTL

长任务跨 5 分钟会导致 prompt 缓存失效、重新写缓存（`cache_creation` 计费）。
给 Claude Code 设置环境变量 `ENABLE_PROMPT_CACHING_1H=1` 把 TTL 提到 1 小时
（详见 README「与 dsh-claude-code 配合：prompt 缓存 TTL」一节）。
